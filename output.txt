CHAPTER I



THE PROBLEM AND ITS SETTING

When a group of individuals works on the same digital file, they often update the text in ways that don't match. To address this challenge, the research team developed a software solution that automatically manages overlapping inputs. The engine compiles multiple versions of documents in the background, preventing accidental data loss. This implies that everyone in the group can still see the same, up-to-date material without using too much bandwidth.

Introduction

In modern academic and professional environments, users increasingly rely on multiple edge devices distributed across various locations to execute shared digital tasks. As collaborative teams manage institutional records, codebases, and research data, they expect uninterrupted, real-time access to their shared workspaces. However, when multiple individuals open and alter the exact same document simultaneously, this collaborative workflow often worsen. Overlapping modifications frequently collide, generating chaotic, out-of-sync copies of the original file. Instead of focusing on productivity, users are forced to halt their operations and manually cross-reference divergent documents to determine which edits should be preserved and which must be discarded. This reliance on human intervention exposes digital workflows to significant systemic risks, severe administrative fatigue, and the constant threat of accidental data loss.

The academic literature confirms these structural vulnerabilities and the critical need for automated intervention. The modernization of enterprise architecture demonstrates a massive shift toward distributed systems, enabling substantial digital collaboration across event-driven cloud environments [1], [10]. However, when multiple individuals attempt to access a file simultaneously, managing the temporal consistency of data becomes a critical bottleneck, as synchronization delays completely break the user experience during financial or administrative data processing [5]. Legacy methods fail in these offline-first environments, requiring robust data consistency models to balance the tradeoffs of the CAP theorem and manage divergent states safely [6]. Without an automated engine, decentralized edge nodes struggle to verify and order operations correctly when users transition back online [7].

An online working environment strictly requires technology that facilitates real-time collaboration. Engineers frequently deploy algorithmic models like Conflict-Free Replicated Data Types (CRDTs) to solve these data collisions, transitioning away from server-locked databases toward coordination-free mathematical models [20]. However, pure CRDTs struggle with severe memory constraints; implementing robust synchronization requires significant structural improvements, such as shifting to log-based CRDT approaches [11]. To bypass these limitations, this study develops a hybrid automated approach. By systematically integrating Log-Based Synchronization to improve observability in event sourcing [2], Vector Clocks utilizing tree clock data structures to enforce strict causal orderings [8], and Last-Write-Wins (LWW) logic for efficient edge data synchronization [45], the architecture mathematically enforces causal order. Furthermore, to overcome bandwidth efficiency limits, the system utilizes Delta Encoding, executing fast byte-level differencing to aggressively compress the transmission payload [3], [4]. This optimization ensures that all users view identical, up-to-date material without saturating the network, ultimately eliminating the hazardous need for manual file reconciliation.

Scope and Limitation

The system uses a hybrid synchronization engine to fix file conflicts and keep data updated. It operates on an eventual consistency model instead of strict realtime collaboration. It works on many devices, such as computers, web browsers, and mobile phones, letting users connect to their local files easily. To sync files without a central server, the engine uses Log based synchronization, Vector clocks, and Delta encoding.

The system manages the complete file lifecycle. Users insert new content, modify existing words and paragraphs, or remove text entirely. The engine exclusively processes text-based formats, structured data, and markup languages. Supported extensions include .txt, .docx, .rtf, .csv, .json, .xml, .md, .html, and .tex. The architecture rejects opaque binary media, such as images, audio, video, and compiled executables. These binary formats shift internal data blocks unpredictably and break the delta encoding sequence. The system excludes encrypted or proprietary formats requiring closed API access. 

When multiple people edit a single document at the same time, the system uses a Last Write Wins mechanism to automatically resolve the conflict. It also provides a version history of the document, so users can track changes and easily revert to older versions if they accidentally overwrite something. Furthermore, the system includes a real-time owner notification module, wherein the document owner receives an in-app alert to review and accept or reject any automated merge, and upon acceptance, the system immediately notifies all connected collaborators that the document has been officially updated. Because the system relies on eventual consistency, conflict resolution happens in the background when users transition from an offline to an online state.

The technical evaluation scope was strategically designed to validate the hybrid synchronization engine's fault tolerance and operational efficiency under realistic edge computing constraints. Specifically, the system is scoped and tested to handle a maximum of (1) 15 concurrent users editing a single shared document at the exact same time, which accurately reflects standard collaborative group sizes in academic environments while ensuring the computational load remains manageable for resource-constrained student laptops executing localized Last-Write-Wins arbitration. To rigorously assess the engine's backend data convergence, this testing involves a total of (2) 25 to 30 conflict scenarios deliberately created to simulate overlapping edits under controlled conditions, providing a deterministic baseline to empirically measure conflict detection rates and intent preservation without structural corruption. Furthermore, testing is conducted across (3) multiple file types, including .txt, .docx, .rtf, .csv, .json, .xml, .md, .html, and .text files, to assess the system's behavior across varying content formats and validate the Delta Encoding module's capacity to safely execute byte-level differencing. Finally, the synchronization mechanism is evaluated at a frequency of up to (4) 10 synchronization events per second to approximate real-world collaborative activity, simultaneously testing the local parsing engine and network transport layer to precisely quantify system throughput, latency, and real-time responsiveness without artificially crashing the localized network infrastructure.

Performance is measured using the following metrics: (5) latency, recorded in milliseconds to capture the delay between an edit being made and its propagation to all connected devices; (6) throughput, expressed in updates per second to quantify the volume of synchronization events the system can process without degradation; (7) conflict resolution time, measured in milliseconds from the moment a collision is detected to the moment the resolved delta is transmitted; (8) data loss rate, calculated as the percentage of user edits that failed to persist after an automated merge; (9) (10) consistency success rate, representing the proportion of synchronization attempts that produced an identical final document state across all connected devices; and (11) system scalability, assessed by observing how performance across these metrics shifts as the number of concurrent users increases from a single session up to the maximum of 15. This limit reflects standard group sizes in the university while keeping the processing load manageable for local devices.

Importantly, this study compares the proposed design with standard algorithms. Specifically, Google Drive and Google Docs were selected as the primary empirical baselines because they are recognized industry-standard systems. Google Drive employs a proprietary ownership-locking and version-stamping mechanism for file-level conflict resolution, while Google Docs implements Operational Transformation (OT) for real-time character-level synchronization. Building the full software for these two algorithms is outside the scope of this project, but they serve as the main theoretical baselines. The research looks into whether the new combination of algorithms is a better alternative to their known flaws. To empirically validate this comparison, the technical evaluation focuses exactly on specific performance numbers. (1) is Conflict Detection Rate, which is measured when the engine compares vector clocks and quantifies the percentage of overlapping edits successfully identified. (2)The second is the Number of Unresolved Conflicts, counted when the automated Last Write Wins logic fails and escalates the merge to the document owner for manual review. (3) Conflict Resolution Accuracy, calculated after arbitration to verify what proportion of the automated merges preserved user edits without structural corruption.(4) Resolution Time, recorded in milliseconds to measure the exact elapsed duration from the moment the engine detects a data collision to the moment it transmits the delta payload. (5) Data Consistency Rate is measured at the end of the procedure to determine the percentage of sync attempts that successfully produced an identical final file state across every connected device.

Additionally, an Edge Computing and Local Execution Module handles tasks directly on the device instead of sending them to a server, which reduces system delays. A Bandwidth Improvement Module sends only the changed parts of the file using delta encoding, removing the need to send the whole file. This method saves network data and speeds up the syncing process, completely avoiding the need to constantly talk to a server.

The researchers set specific boundaries for the system. The software will be used strictly inside the academic setup of Pamantasan ng Cabuyao as a local tool to help students and teachers sync their documents. Files are divided into fixed 4MB chunks. Finally, while the system protects the structural integrity of the data using mathematical ordering, advanced network security is not included. The scope of this study focuses purely on algorithmic file synchronization. Therefore, integrating complex data encryption or advanced network security protocols is outside the current scope of this research.

Conceptual Literature

Standard Features 

Modern distributed architectures require decentralized frameworks to maintain strict data integrity across offline-first environments. Enterprise systems adopt event-driven topologies to separate data generation at the edge from long-term central storage processes [1]. This architectural design triggers asynchronous workflows based on discrete state changes rather than polling databases continuously, which successfully decouples system components to increase overall transaction throughput [2]. Event sourcing treats every state change as an immutable record rather than executing destructive overwrites on existing database values. System observability improves significantly when engineers track these distinct atomic events instead of mutable final states, as the append-only design provides an exact cryptographic audit trail for system recovery [3].



Traditional synchronization engines rely heavily on standard Conflict-Free Replicated Data Types (CRDTs), which exhibit severe memory limitations by permanently accumulating metadata tombstones for every deleted object. Log-based virtual file systems offer a highly scalable alternative by sequencing operations through an immutable log and discarding obsolete intermediate events through structured log compaction [4]. Algebraic replicated data types abstract these operations further, reducing the computational footprint required to merge divergent states by applying strict algebraic properties to the underlying data structures [5]. Furthermore, robust synchronization protocols apply temporal consistency models to ensure systems process financial and operational data in the correct chronological sequence [6]. This strict temporal ordering guarantees that independent nodes apply updates deterministically, thereby preventing race conditions when remote devices reconnect to the primary network.



High-latency networks demand highly efficient data transfer mechanisms, as full-state synchronization consumes excessive bandwidth and CPU cycles during partition recovery. Storage systems implement advanced delta encoding to isolate and transmit only the modified bytes between differing file versions [7]. Encrypted cloud architectures combine fast delta synchronization with advanced content-defined chunking algorithms to decrease network overhead across the transport layer [8]. Content-defined chunking establishes dynamic segment boundaries based on the file content itself rather than relying on static block sizes, preventing catastrophic byte-shifting anomalies during localized edits. These mechanisms prioritize transmission speed and payload accuracy over legacy full-file transfer methods in resource-constrained environments.



Guidelines for Using the Algorithms

Distributed network environments operate under strict CAP theorem constraints, mandating a mathematically calculated trade-off between consistency and availability during network partitions [9]. Offline-first applications require uninterrupted local availability to function effectively, dictating the adoption of causal consistency models over rigid strong consistency protocols. Causal consistency guarantees that distributed nodes observe related operations in the exact chronological sequence of execution. Independent nodes determine the precise order of parallel edits to resolve conflicts deterministically. This rigorous mathematical ordering prevents catastrophic data loss and state divergence during asynchronous file merging procedures.



Masterless algorithms track causality through time-based logical structures rather than relying on vulnerable centralized coordinators. Asynchronous architectures achieve strict causality by mapping physical clocks directly to decentralized edge nodes [10]. This hybrid tracking approach actively mitigates the timing drift inherent in standard Network Time Protocol synchronization. Local nodes assign an immutable logical timestamp to every user action at the exact moment of execution. The underlying synchronization engine compiles these timestamps to construct a directed acyclic graph (DAG) of file histories. This applied mathematical graph exposes concurrent edits and sequence anomalies instantly, eliminating the latency dependency of a central server arbitration.



Processing massive operational histories requires highly optimized computational data structures. Modern asynchronous architectures deploy tree clock data structures to accelerate causal orderings during concurrent executions [11]. Hierarchical tree models completely bypass the linear O(N) computational bottlenecks endemic to traditional flat vector clocks. Furthermore, resettable encoded vector clocks provide essential mathematical fail-safes for decentralized networks. These strict protocols prevent integer overflow during prolonged offline periods by systematically compressing and resetting local counter arrays when bounds are exceeded [12]. Deploying these advanced mechanisms allows edge nodes to resolve complex edit collisions securely, establishing a highly scalable foundation for log-based conflict resolution.

Clear visual feedback mitigates the data loss anxiety typically experienced during prolonged offline periods. Application dashboards integrate these specific UX principles to facilitate seamless peer-to-peer collaboration without central oversight. Intuitive navigation structures reduce the cognitive load required to manage distributed file hierarchies. Review of Related Literature 

Consistency Models in Distributed Systems

The modernization of enterprise infrastructure requires scalable technological solutions to replace outdated, isolated analog workflows. As institutions accelerate their transition toward globalized, digital governance, the demand for concurrent multi-user access to shared resources has grown exponentially. Organizations can no longer rely on asynchronous communication methods that inherently cause severe administrative delays and operational inefficiencies. To achieve high-speed throughput and maintain competitive operational agility, systems must support simultaneous multi-node access without degrading the integrity of the underlying data structures. This overarching shift demonstrates that digital technologies have significantly transformed the workplace, enabling substantial collaboration [1].

Historically, file management in collaborative environments relied on pessimistic mechanisms like file-locking, which restricted access to a single user at a time to prevent overlapping edits. While this prevented data corruption, it systematically destroyed the real-time collaborative potential of distributed teams. As organizational workflows scale across geographically separated computing nodes, enforcing sequential access creates unacceptable administrative delays and throttles institutional throughput. In modern decentralized networks, traditional file locking methods are ineffective when jobs are distributed across multiple machines [2].



To bypass the limitations of legacy file-locking, modern architectural frameworks rely on optimistic concurrency models designed to process simultaneous modifications gracefully rather than preventing them entirely. Academic discourse in collaborative computing primarily categorizes the most viable solutions into two predominant methodologies that resolve the inevitable data collisions that occur during parallel execution. Therefore, to manage concurrent states effectively, engineers use two of their most important tools: Operational Transformation (OT) and Conflict-Free Replicated Data Types (CRDTs) [3].



These algebraic data structures neutralize the vulnerabilities of centralized server architectures by natively enforcing a masterless convergence protocol. As established in the foundational work of Werner Vogels on Eventual Consistency, distributed systems can remain highly available and partition-tolerant as long as all replicas are guaranteed to independently converge to the exact same state once no new updates are made. Utilizing commutative operations ensures that regardless of the chronological order or network delays involved in receiving data packets, all local replicas will independently calculate the identical final document state. To solve the problem, algorithmic models have been developed. One of these is CRDTs, which ensure Strong Eventual Consistency in distributed systems by allowing replicas to update and merge their changes without a central server [4].



Despite these advancements, achieving perfect, instantaneous synchronization involves significant architectural trade-offs between system speed and strict accuracy. This systemic limitation is mathematically formalized by Eric Brewer’s CAP Theorem, which dictates that a distributed data store can only simultaneously provide two of three guarantees: Consistency, Availability, and Partition tolerance. Because modern offline-first applications must remain available during network drops, engineers are forced to sacrifice strict real-time parity, creating a brief window of asynchronous delay where file versions temporarily differ. Adhering to these constraints, the system utilizes a hybrid Synchronization Engine to resolve conflicts and maintain file synchronization, operating on an eventual consistency model rather than strict real-time collaboration [5].



Current systems engineering research heavily advocates that utilizing a single algorithmic framework is fundamentally insufficient to resolve the multifaceted engineering challenges inherent in highly available distributed computing. While transformation-based logic excels at preserving the exact semantic intent of overlapping text, it lacks the masterless state convergence required for offline networks. To construct an architecture that balances zero-trust fault tolerance with precise character-level conflict resolution, developers must synthesize these contrasting mathematical realities. Establishing a new baseline for autonomous collaborative platforms, hybrid approaches combine the strengths of OT and CRDT to address distributed system issues [6].



Casual Tracking and Intent Preservation

The historical overreliance on heuristic, human-driven intervention to reconcile diverging file states introduces significant systemic risk into digital workflows. When legacy network drives fail to automatically track the chronological causality of parallel edits, users are forced into the highly inefficient position of manually cross-referencing and merging conflicting document versions. This labor-intensive process inevitably leads to severe administrative fatigue, heightening the probability of accidental data overwrites and subjective merging errors. Research shows that older technology, including network drives, doesn't easily combine several changes. Users must manually resolve conflicts [7].



In the absence of complex causal tracking algorithms, early automated systems relied on rudimentary timestamp arbitrations to resolve data conflicts. While computationally inexpensive and easy to deploy, these protocols are inherently destructive for multi-author text environments; they blindly overwrite parallel edits based solely on the latest clock timestamp, entirely disregarding the substantive value of the overridden data. Because it leads to silent data loss and fails to provide an immutable audit trail for forensic recovery, simple strategies like Last Write Wins often result in insufficient documentation and become difficult to use when you need to find a solution [8].



To explicitly preserve the original semantic intent of concurrent authors, conflict resolution engines must comprehensively analyze spatial data parameters rather than relying purely on temporal markers. If two users type in the exact same paragraph simultaneously, the algorithm must intercept the remote data packet, recalculate its intended spatial coordinate against the new local layout, and insert the characters dynamically to prevent structural corruption and overlapping text anomalies. Providing this highly granular, character-level preservation of user intent, on the other hand, the OT algorithm tracks users' actions while editing text together by dynamically recalculating the positional indexes of text changes [9].



While highly effective at localized index recalculation and semantic preservation, classic transformation architectures possess a fatal flaw when deployed in decentralized environments. They are heavily reliant on a single, centralized server to sequence operations; if the network experiences severe latency or offline partition failures, the central arbiter cannot dictate the absolute order of transformations, causing the system to stall or infinitely loop. Earlier research has demonstrated that pure OT algorithms typically cannot manage synchronization delay independently and require a central server [10].



To successfully bypass this centralized bottleneck, advanced peer-to-peer networks utilize logical tracking frameworks as their primary mathematical fail-safe. These frameworks assign an array of logical timestamps to every localized edit, allowing disparate hardware nodes to independently map out the exact chronological sequence of operations even if those operations occurred completely offline. By pairing these logical clocks with an immutable background architecture, the framework guarantees that all decentralized clients process the history of document changes in the exact same mathematical order. To achieve decentralized synchronization without a central server, the engine implements Log-based synchronization, Vector clocks, and Delta encoding [11].



Log-Based Theory & Bandwidth Optimization

Offline-first environments severely stress the architectural and computational limits of standard distributed databases. When users operate in disconnected states, local applications continue to generate modifications that continuously diverge from the global network state. Upon eventual reconnection, the sudden influx of queued, unsynchronized data can trigger massive CPU spikes and severe network congestion, causing systemic lag as the underlying engine struggles to reconcile the isolated branches of data against the primary repository. The performance of a distributed system drops significantly when synchronization fails or a user is offline [12].



To decisively mitigate the risk of catastrophic overwrites during high-stress reconnection phases, advanced architectural models employ event-sourcing and log-based theories. Rather than executing direct, destructive mutations to a central database value, the system securely records every isolated keystroke or file modification as a discrete, append-only event in a background sequence. This hidden log compilation acts as an exact cryptographic audit trail, ensuring that conflicting document versions are preserved safely in memory until the engine mathematically determines the optimal, loss-free convergence path. The engine compiles multiple versions of documents in the background, preventing accidental data loss [13].



The sheer volume of causal metadata generated by peer-to-peer frameworks frequently overwhelms the physical constraints of network bandwidth, particularly in environments utilizing decentralized architectures. In scenarios characterized by high latency or unstable internet service providers, transmitting heavy, fully replicated causal histories for every minor text edit creates an immediate and severe performance bottleneck. Distributed computing literature heavily emphasizes that optimizing transport layer payloads is a mandatory, non-negotiable requirement, as edge cloud systems need significant development to run faster. Bandwidth efficiency limits performance [14].



To achieve maximum network efficiency and resolve latency bottlenecks, modern storage protocols aggressively abandon legacy full-file transfer methods in favor of optimized differential synchronization. By utilizing advanced content-defined chunking and byte-level comparison algorithms, the system mathematically isolates only the specific characters or blocks that were altered during an offline collaborative session. To drastically accelerate synchronization speeds and preserve critical network bandwidth, a Bandwidth Improvement Module transmits only the modified file sections via delta encoding, eliminating the need for full file transfers [15].



The ultimate operational goal of these combined synchronization architectures is to process conflict resolution in the background without overwhelming edge devices or saturating the local area network. By strictly transmitting microscopic delta payloads rather than resending multi-megabyte documents, the system ensures that highly concurrent user environments remain responsive. By successfully masking the computational weight of the background merge process, this implies that everyone in the group can still see the same, up-to-date material without using too much bandwidth [16]. 	Modern collaborative systems must securely synchronize a wide variety of files, ranging from simple text documents to complex, non-textual items like images, encrypted data, and system backups. Older synchronization methods frequently corrupt these complex files because they attempt to read and modify the specific internal structure of the document. To resolve this, the system developed by the researchers ignores the file format entirely and instead processes every document as a simple stream of raw data. [53], identifying and syncing only the exact raw data changes, rather than trying to interpret the actual content, allows a system to process any file type safely and efficiently. This direct approach is proven to successfully handle massive, highly complex files, such as virtual machine images and database backups, without causing any structural damage or data loss. Ultimately, by extracting and transferring only the exact pieces of data that were modified, the proposed architecture guarantees that end-users receive fast, perfectly matched file updates without overloading the institutional network.

Review of Related Studies

Peer-To-Peer Logs

Modern enterprise architecture [1] and event-driven cloud computing [10] increasingly rely on decentralized models to maintain distributed state. At the core of these structures is log-based synchronization, which shifts from traditional state-overwriting to append-only operational logging. Unlike Operational Transformation (OT), which was fundamentally designed around client-server architectures and requires a centralized sequential arbiter to transform concurrent operations, log-based peer-to-peer models natively decouple state machine execution from log replication. This decentralized approach allows systems to achieve significantly higher consensus throughput and structural security without centralized bottlenecks, particularly in complex IoT and consortium-blockchain networks [26]. Optimization of underlying peer-to-peer consensus, such as in RaftOptima architectures, focuses on minimizing latency while enhancing fault tolerance across distributed nodes [27].

To enforce causal order in these masterless environments, engineers often employ Vector Clocks and gossip protocols for anti-entropy analysis [31]. However, maintaining strict causal histories introduces severe metadata overhead. This structural limitation is highly evident in Conflict-Free Replicated Data Types (CRDTs), which, while functioning without a central server, burden peer-to-peer connections by forcing nodes to compute, store, and transmit extensive state histories and mathematical tombstone markers to guarantee eventual consistency. Consequently, Last-Write-Wins (LWW) is utilized as a fundamental, low-overhead strategy for high-concurrency writes, especially on resource-constrained edge devices [39], [40], [42]. Unlike the heavy computational state-merging required by CRDTs or the synchronous coordination of OT, LWW provides a streamlined path to convergence by using simple wall-clock or logical timestamps to resolve updates. Furthermore, the use of hybrid consensus models [28] and flexible erasure coding in log replication sequences reduces computational costs and enables ultra-fast recovery during network partitioning [29], facilitating effective transaction processing across heterogeneous, high-latency nodes [30].



Bandwidth Optimization

To overcome the physical constraints of network throttling in real-time collaboration, modern synchronization engines have shifted toward a primary stack comprising Log-based Synchronization, Vector Clocks, Delta Encoding, and Last-Write-Wins (LWW). This integrated approach prioritizes network efficiency by strictly isolating byte-level differences via Delta Encoding to reduce transmission payloads [3]. Within encrypted cloud designs, FAST sync schemes leverage this logic to ensure that data security does not compromise network responsiveness [4].

The inherent efficiency of this stack is most evident when contrasted with Conflict-free Replicated Data Types (CRDTs) or Operational Transformation (OT). While CRDTs require the transmission of extensive causal history and unique identifiers for every operation, LWW-based state synchronization consumes significantly less energy and bandwidth because it only requires a single timestamp for resolution [45]. Similarly, while OT demands constant server-side coordination and frequent re-transmission of operations to maintain consistency, the combination of delta encoding and log-based logs allows for massive network savings by focusing on raw state parity rather than complex transformation logic. Advanced techniques, including transaction log compression [33] and adaptive linear updates for time-series data [34], further enhance this performance, ensuring shared assets remain synchronized with minimal overhead [35]. Even when dealing with large-scale datasets like container image updates, the utilization of encoded delta payloads rather than full file transfers ensures that the system maintains a real-time experience for concurrent end-users without saturating the available bandwidth [32].

A mathematical principle formalized by Eric Brewer dictating that a distributed data store can only simultaneously provide two of three guarantees: Consistency, Availability, and Partition tolerance. [6]

Algebraic data structures that ensure strong eventual consistency in distributed systems by allowing replicas to update and merge changes without requiring a central server, utilizing commutative operations to guarantee convergence regardless of operation order. [4], [6], [20]

Content-Defined Chunking (CDC)

A dynamic segmentation method that establishes file block boundaries based on file content rather than static sizes, preventing byte-shifting anomalies during localized edits. [3], [4]

Delta Encoding

A byte-level differential synchronization technique that isolates and transmits only modified file segments between differing versions, drastically reducing network payloads by avoiding full file transfers. [3], [4], [32]

Last-Write-Wins (LWW)

A low-overhead conflict arbitration mechanism that resolves concurrent updates using timestamps, providing a streamlined path to deterministic convergence without requiring complex state merging.[45]

Operational Transformation (OT)

A coordination-free collaborative replication framework that preserves user intent during concurrent text editing by dynamically recalculating positional indexes of text changes, enabling simultaneous multi-user modifications without data corruption. [9], [21], [29]

Strong Eventual Consistency (SEC)

A convergence guarantee ensuring that all replicas in a distributed system will independently calculate the identical final document state once no new updates are made, without requiring a central coordinator. [4], [20]

System Usability Scale (SUS)

A standardized quantitative metric for evaluating user experience in specialized asynchronous environments, measuring interface efficiency, discoverability, and user satisfaction. [13]

Complexity Analysis 

The hybrid synchronization solution replaces legacy frameworks by implementing Log-based Synchronization, Vector Clocks, Last-Write-Wins (LWW) arbitration, and Delta Encoding [26], [32]. It automatically resolves file conflicts through a three-step deterministic procedure. First, the system records concurrent modifications as immutable, append-only log events rather than executing destructive overwrites [2]. Second, the engine evaluates Vector Clocks to establish strict causal histories across all decentralized nodes [8]. Third, it applies LWW logic and Delta Encoding to converge the data accurately [45], ensuring all versions on the network remain mathematically identical without a central server [20].

The computational overhead of the algorithm scales efficiently. When processing a concurrent event, comparing Vector Clocks requires O(m) time, where  represents the number of active replica nodes [18]. Unlike pure Operational Transformation (OT), which requires O(n^2) time to recalculate positional indexes for n concurrent operations [9], the proposed architecture relies on sequential log evaluation and LWW logic for conflict resolution. Because of this streamlined arbitration mechanism, the conflict resolution process avoids heavy transformation math, executing in O(m) time overall [45], [48]. This reduction in computational cost allows the engine to maintain high performance during rapid, simultaneous editing sessions.

Space complexity scales linearly at O(n+m) [6]. The system maintains operational metadata, including logical timestamps, node identifiers, and isolated delta payloads [3]. To ensure strict causal consistency, each decentralized replica must store a version vector, requiring O(m) memory [8]. By abandoning the heavy tombstone metadata required by pure CRDTs [11] and employing Delta Encoding to compress transmission payloads, the architecture significantly reduces both memory utilization and bandwidth consumption during long-term collaborative sessions [32], [34].

The evaluation quantifies system throughput, synchronization latency, and data loss rates under simulated concurrent editing stress. Finally, the chapter compares the usability and technical performance of the proposed solution directly against established industry baselines. This comparison incorporates automated system logs and ISO/IEC 25010 survey responses from both technical and non-technical participant groups. The findings verify the exact level of user acceptance and algorithmic reliability achieved by the hybrid architecture.





Implementation of the Hybrid Synchronization Engine

The study's primary problem is that collaborators editing the same shared document, especially over a peer-to-peer connection with no central server, can produce conflicting versions that are difficult to reconcile safely. A change made by one device can be overwritten by another without warning, particularly when neither device is aware of what the other has done. In order to solve this, the study investigates whether combining an append-only event log, hierarchical logical clocks, an owner-arbitrated resolution step, and byte-level delta encoding can keep concurrent edits consistent without discarding a collaborator's work without notice.

With the help of the working prototype, the researchers were able to run controlled edit scenarios between simulated peer devices and observe how the engine actually behaves when two edits touch the same document. This way, the study provides not only a description of the intended design but also a concrete trace of how a single edit moves through the system in practice. The following sections present this trace and connect each step back to the research question.

Real-time collaborative editing is challenging because concurrent edits are common and network connectivity between peer devices cannot be guaranteed at every moment. To address this, the engine avoids relying on a single authoritative server and instead lets each device log its own edits locally and reconcile them once a connection is available. These mechanisms work together to keep edit history intact, causal order determinable, and network usage light; however, as the discussion below shows, the way they interact changes depending on whether the conflicting devices are reconnecting after time offline or editing at the same moment in real time, and this distinction has a direct effect on how safely conflicts are resolved.

The engine preserves every collaborator's edit, removes the ambiguity between sequential and concurrent changes, and keeps network usage low through the combined effect of the four integrated mechanisms described in Chapter III. No edit is lost outright because the Peer Manager writes every modification to an append-only event log before anything else happens, so even a change that is later superseded remains recoverable in the log rather than being deleted. Ambiguity between sequential and concurrent edits is removed because each logged event carries a Tree Clock timestamp, a hierarchical counter that lets the engine compare two edits' causal history instead of relying on the physical clock of either device, which may drift or fall out of sync. Once two edits are identified as concurrent, the engine's response depends on the connection context in which the conflict is found, which is the detail the remainder of this section documents in full.

Conflict Resolution for Offline-Reconnect Edits. When an offline device reconnects, the Peer Manager compares its changes with the shared version through a three-way merge. If the edits affect different parts of the file, the system merges them automatically and records the result in the conflict log. If both edits affect the same part, the conflict is sent to the document owner for review and resolution.

Conflict Resolution for Live, Real-Time Edits. For users editing at the same time while online, the Tree Clock identifies the changes as concurrent. In the current implementation, the system resolves these conflicts using physical timestamps and keeps the more recent edit. This differs from the intended owner-arbitrated approach and presents a limitation because differences between device clocks may cause one user's changes to be overwritten without notification.

Delta Encoding and Update Propagation. After the system resolves a conflict, Delta Encoding identifies only the changed parts of the file and sends them to the connected devices. The receiving device applies these changes to its local copy instead of downloading the entire file. A checksum then verifies the updated file before it is treated as complete.
